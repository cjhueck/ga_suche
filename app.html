1. Projektübersicht

Zweck: Inhaltliche Orientierung und Recherche in der Rudolf Steiner Gesamtausgabe (GA)

Umfang: Ca. 350 GA-Bände mit über 6000 Vorträgen und Schriften

Technologie:

  • Frontend: HTML5, CSS3, JavaScript (ES6+) - Single Page Application in app.html
  • Backend: Node.js mit Express (backend.js)
  • KI-Integration: Claude API (Anthropic), DeepSeek, OpenAI via llm-providers.js
  • Datenbank: JSON-basiert (keine SQL-Datenbank)
  • Hosting: Render.com (Online), localhost:3003 (Lokal)

3. Datenquellen

Obsichan

Verwendung: Primäre Bearbeitung der Vorträge und Schlagwörter

  • Vorträge als Markdown-Dateien in Steiner_GA/GAXXX-Titel/
  • Schlagwörter mit Wiki-Links: [[Schlagwort]]
  • Quellenverweise: ([[GA078 (1.) TITEL|GA078/1]])
  • Zeilenumbrüche: /br Markierungen
  • Export via scripts/export_from_md.py oder Obsichan-Plugins

Pfad: Die Markdown-Dateien werden in JSON konvertiert und in steiner-full-lectures/ gespeichert.

Citavi

Verwendung: Bibliographische Angaben für GA-Bände

  • Citavi-Projektdatei: .ctv6 (SQLite-Datenbank)
  • Enthält: Titel, Autor, Verlag, Jahr, Ort, ISBN, Band-Nummern
  • Export via extract_citavi_bibliography.py
  • Ziel: ga-bibliography.json

Pfad: C:\Users\...\Citavi 7\Projects\Rudolf Steiner Gesamtausgabe\*.ctv6

Frei verfügbare GA-Texte

Die Vortrags-Texte stammen aus frei im Internet verfügbaren Versionen der GA. Diese wurden in Obsichan importiert, strukturiert und mit KI-generierten Zusammenfassungen und Zwischenüberschriften versehen.

4. Datenverarbeitung

Vorträge (Lectures)

  1. Quelle: Markdown-Dateien in Obsichan
    Steiner_GA/GAXXX-Titel/GAXXX (N.) Vortragstitel.md
  2. Export: Python-Skripte konvertieren MD → JSON
    scripts/export_from_md.py, export_master.py
  3. Ziel: steiner-full-lectures/steiner-full-lectures-XXX-YYY-partNN.json
  4. Struktur: Jeder Vortrag enthält:
    • ID: z.B. "GA078/1"
    • gaNumber: z.B. "GA078"
    • title: Vortragstitel
    • date: Datum
    • location: Ort
    • paragraphs[]: Absätze mit content und index

Schlagwörter (Keywords/Concepts)

  1. Erstellung: KI-generiert oder manuell in Obsichan
  2. Speicherung:
    • concepts-database.json - Hauptdatenbank für Index-Tab
    • keywords-database.json - Vortragsspezifische Keywords
    • Keywords/*.json - Alphabetisch sortiert (A.json, B.json, ...)
  3. Verarbeitung: Zusammenfassung ähnlicher Einträge mit Claude AI

Wandtafelzeichnungen

Zweck: Wandtafelzeichnungen Rudolf Steiners werden den entsprechenden Vorträgen zugeordnet und als klickbare Galerie unter dem Vortragstext angezeigt.

Quellen & Ordner:
Ordner Beschreibung
Steiner_GA/chalkboards/ Quellordner (PNG/WebP) – Neue Bilder hier ablegen
chalkboards/ Git-Repository-Ordner (WebP) – Wird automatisch synchronisiert
chalkboards.json Index aller Tafeln mit Metadaten (GA, Datum, Tafel-Nr.)
Namenskonvention:
  • GA076-1921-04-05-T01.webp – Standard: GA + Datum + Tafel-Nummer
  • GA316-1924-04-24a-T01.webp – Mit Suffix a für zweiten Vortrag am selben Tag
  • GA316-1924-04-24a-T02.webp – Zweite Tafel des zweiten Vortrags
Workflow (Schritt für Schritt):
  1. Bilder ablegen:
    Neue Wandtafelbilder (PNG oder WebP) im Ordner Steiner_GA/chalkboards/GAxxxx/ ablegen. Die Unterordner sind nach GA-Nummer benannt (z.B. GA316/).
  2. Export-Skript ausführen:
    python scripts/generate_chalkboards_json.py
    • Konvertiert PNG → WebP automatisch
    • Parst Dateinamen (GA, Datum, Tafel-Nr., Suffix)
    • Erstellt/aktualisiert chalkboards.json
    • Synchronisiert nach chalkboards/ (für Git)
  3. Import in Vorträge:
    python scripts/import_chalkboards_to_lectures.py
    • Lädt chalkboards.json
    • Findet passende Vorträge anhand GA + Datum + Suffix
    • Fügt Tafel-Paragraphen am Ende des Vortrags ein
    • Entfernt alte Tafel-Paragraphen automatisch (bei Löschung von Bildern)
  4. ⚠️ Git Push:
    Der Ordner chalkboards/ muss nach dem Export manuell gepusht werden:
    • GitHub Desktop öffnen
    • Änderungen im chalkboards/ Ordner committen
    • Push zum Remote-Repository
Matching bei mehreren Vorträgen am selben Tag:

Wenn es mehrere Vorträge am selben Tag gibt (z.B. Morgen- und Abendvortrag), wird ein Suffix (a, b, etc.) verwendet:

Dateiname → Vortragstitel enthält
GA316-1924-04-24-T01.webp 24. April 1924 (erster Vortrag)
GA316-1924-04-24a-T01.webp 24. April 1924a (zweiter Vortrag)

Das Suffix im Dateinamen (z.B. a) wird mit dem Suffix im Vortragstitel/-dateinamen abgeglichen.

Automatische Bereinigung:
  • Wenn ein Bild aus Steiner_GA/chalkboards/ gelöscht wird, wird es beim nächsten generate_chalkboards_json.py-Lauf auch aus chalkboards/ entfernt
  • Beim import_chalkboards_to_lectures.py-Lauf werden alte Tafel-Paragraphen automatisch entfernt, bevor neue eingefügt werden
  • Der TOC-Link "Wandtafelzeichnungen" erscheint/verschwindet automatisch je nach Vorhandensein von Tafeln

Seitenzahlen (Page Breaks)

Zweck: Seitenzahlen aus den gedruckten GA-Bänden werden in die JSON-Vorträge eingefügt, damit Nutzer die Original-Seitenzahlen sehen können.

Skripte:
Skript Funktion
batch_generate_pagebreaks.py Hauptskript: Führt beide Schritte für GA-Bände aus
export_page_markers_v4.py Extrahiert Seitenumbruch-Marker aus PDF
apply_page_break_markers_v4.py Fügt |page|-Marker in JSON-Vorträge ein
generate_lecture_page_mapping.py Erstellt Mapping: Vortrag-ID → Start-Seitenzahl
Arbeitsweise:
  1. export_page_markers_v4.py:
    • Öffnet PDF aus Steiner_GA_pdf/
    • Erkennt gedruckte Seitenzahlen im Footer ("Seite: X", "- 123 -")
    • Extrahiert Fließtext (ohne Header/Footer/Überschriften)
    • Speichert pro Seitenumbruch: left (200 Zeichen vor), right (200 Zeichen nach)
    • Output: page-break-markers.json
  2. apply_page_break_markers_v4.py:
    • Lädt Break-Anker aus page-break-markers.json
    • Normalisiert Text (lowercase, Ligaturen, alte Rechtschreibung)
    • Findet per Fuzzy-Matching die exakte Einfügeposition im JSON-Text
    • Fügt Marker im Format |14| ein
    • Output: pagebreaks/GA198.json
  3. generate_lecture_page_mapping.py:
    • Sucht ersten Fließtext-Absatz jedes Vortrags im PDF
    • Speichert Start-Seitenzahl pro Vortrag
    • Output: lecture-page-mapping.json
Verwendung:
# Seitenzahlen für eine GA generieren
python batch_generate_pagebreaks.py 198 198

# Mit Lecture-Mapping (für bessere Ergebnisse)
python generate_lecture_page_mapping.py GA198
python batch_generate_pagebreaks.py 198 198

# Server neu starten (lädt neue Pagebreaks)
Get-Process -Name "node" | Stop-Process -Force
node backend.js
Dateien:
  • page-break-markers.json – Break-Anker (left/right-Snippets pro Seitenumbruch)
  • lecture-page-mapping.json – Start-Seitenzahl pro Vortrag
  • pagebreaks/GA*.json – Vorträge mit eingefügten |page|-Markern
  • pagebreaks/GA*-report.json – Statistik (wie viele Breaks eingefügt)

Themen-Tab (Themenschwerpunkte)

Zweck: Visualisierung der thematischen Verteilung aller Texte als Heatmap. Klick auf ein Kästchen öffnet das rechte Side Panel mit Kurzzusammenfassungen der zugeordneten Texte.

Themendefinition (63 feste Themen):

Die Themen sind in der Konstante THEME_KEYWORDS in backend.js hartcodiert (z.B. "Christus / Golgatha", "Reinkarnation & Karma", "Pädagogik / Heilpädagogik"). Jedes Thema hat eine zugehörige Schlagwort-Gruppe (z.B. "Christus Golgatha Logos Weltenwort Auferstehung"), die als Referenz für die KI-Zuordnung dient.

Themenzuordnung (KI-basiert, via Claude):

Die Zuordnung von Texten zu Themen erfolgt nicht über die lectureKeywords aus summary-database.json, sondern über einen separaten KI-basierten Prozess:

Schritt 1 Summary-Text ermitteln – Für jeden Text wird shortSummary || summary aus zwei Quellen geladen:
• summary-database.json (Vorträge, Aufsätze)
• book-chapter-summaries.json (Buchkapitel, z.B. GA001/1–GA001/5)
Schritt 2 Claude ordnet Themen zu – Die Funktion assignThemesWithClaude() sendet den Summary-Text zusammen mit allen 63 Schlagwort-Gruppen an Claude (temperature 0.1). Claude antwortet mit den Nummern der passenden Gruppen. Ein Text kann mehreren Themen zugeordnet werden.
Schritt 3 Speicherung – Die Zuordnungen werden in themes/theme-assignments.json gespeichert.
Format: { "GA093a/1905-10-04": { "themes": ["Christus / Golgatha", "Reinkarnation & Karma"], "assignedAt": "..." } }

Auslösung: POST /api/assign-themes-batch mit { gaPattern: "GA046|GA05[1-9]|GA060" }. Verarbeitet 5 Texte parallel mit 300ms Pause.

Anzeige im Side Panel (Klick auf Heatmap-Kästchen):
Frontend-Funktion openThematicLectureList() in themes/thematic-visualization.js
API-Endpunkt POST /api/get-theme-results-ai mit { themeName }
Angezeigte Summary shortSummary (1–2 Sätze). Fallback: volle summary (6–8 Sätze), wenn keine shortSummary existiert.
Datenquellen & Dateien:
themes/theme-assignments.json Zuordnung Text-ID → Themen (KI-generiert)
summary-database.json Summaries für Vorträge/Aufsätze (Felder: summary, shortSummary)
book-chapter-summaries.json Summaries für Buchkapitel (z.B. GA001/1–GA001/5). Nur summary, meist keine shortSummary.
THEME_KEYWORDS (backend.js) 63 fest definierte Themen mit Schlagwort-Gruppen
themes/thematic-visualization.js Frontend: Heatmap-Rendering, Klick-Handler, Side Panel

Hinweis: Die lectureKeywords in summary-database.json werden für die Themenzuordnung nicht verwendet. Die Zuordnung basiert ausschließlich auf der Summary-Textanalyse durch Claude.

Abfrage-Tab (KI-Suche)

Zweck: KI-gestützte thematische Suche mit natürlicher Sprache. Eine Frage wird zunächst über mehrere Verfahren in passende Textstellen aufgelöst (Retrieval), die anschließend je nach gewähltem Modus von einem Sprachmodell ausgewertet werden.

Eingabefelder:
Thema/Frage Natürlichsprachige Anfrage, z.B. "Was sagt Steiner über das Ich?"
GA-Filter (optional) Suche auf bestimmte GA-Bände beschränken (Multi-Select)
Die vier Analyse-Modi (Radio-Auswahl):

Alle Modi nutzen dieselbe Retrieval-Pipeline (siehe unten); sie unterscheiden sich im Auswertungs-Prompt, im Sprachmodell und im Antwortumfang. Steuerung über thematicMode (Radio-Buttons im Header des Abfrage-Tabs).

Modus Wert Modell Zweck & Verhalten
Tiefe deep Claude Opus 4.8 (CLAUDE_MODEL_DEEP), ~8.000 Tokens Qualitative Tiefenanalyse mit wörtlichen Zitaten und Quellenbezug. Hohe Präzisionsanforderung: Findet das Retrieval nur thematisch ferne Stellen, antwortet der Modus bewusst "keine relevanten Stellen", statt zu raten. Standard.
Breite broad Gemini 2.5 Pro (GEMINI_MODEL_BROAD), ~32.000 Tokens. Fällt auf Claude zurück, wenn Gemini nicht verfügbar ist Umfassende Quellensammlung mit großem Kontextfenster — listet viele Fundstellen breit auf. Toleranter gegenüber schwächeren Treffern als die Tiefenanalyse.
Zitat quote Claude Sonnet 4.6 (CLAUDE_MODEL_QUOTE), Auto-Eskalation auf Opus 4.8, ~6.000 Tokens Findet ein bestimmtes Zitat anhand des sinngemäß beschriebenen Inhalts, wenn der genaue Wortlaut unbekannt ist. Niedrigere Semantik-Schwellen, zusätzliche exakte Phrasen-Suche und ein Halluzinations-Filter (jedes ausgegebene Zitat muss wörtlich im Korpus stehen).
Essay essay Claude Opus 4.8 (CLAUDE_MODEL_DEEP), ~16.000 Tokens Mehrstufige Synthese mit expliziter Trennung von Belegen (klickbar verlinkte Steiner-Zitate) und Deutungen (Einordnungen, eigene Lesarten). Belege werden gegen den Quellenpool validiert; Abweichungen vom Originaltext werden mit ⚠ markiert (Zitat-Drift).
Such-/Retrieval-Pipeline (für alle Modi gleich):

Die Anfrage wird über vier Verfahren parallel in Kandidaten-Stellen aufgelöst, die danach gerankt (applySemanticRanking()) und an das modusabhängige Sprachmodell übergeben werden.

1. Stichwortsuche Literale Treffer in allen Absätzen. performThematicKeywordSearch()
2. Query-Expansion Ein LLM erzeugt verwandte Begriffe, die zusätzlich literal gesucht werden. expandQueryWithLLM()
3. Semantik (Vorträge) Kosinus-Ähnlichkeit der Frage zu den Vortrags-Zusammenfassungen. findSemanticallySimilarLectures() — Quelle: summary-embeddings.json
4. Semantik (Absätze) Präzisere Ähnlichkeit auf Absatz-Ebene. findSemanticallySimilarParagraphs() — Quelle: Cloudflare Vectorize (online), Fallback paragraph-embeddings/*.json
⚠ Voraussetzung – Embedding-Schlüssel: Die semantischen Schritte 3 und 4 brauchen ein Query-Embedding. Dieses wird über Gemini embedding-001 (768 Dimensionen) erzeugt (createEmbedding()); dazu muss GEMINI_API_KEY gesetzt sein.
  • Lokal: Schlüssel steht in .env → Semantik aktiv → differenzierte Antworten.
  • Online (Render): GEMINI_API_KEY muss als Umgebungsvariable im Render-Dashboard hinterlegt sein. Fehlt er, scheitert createEmbedding() stillschweigend, die Schritte 3 + 4 (inkl. Vectorize) liefern nichts, und nur die literale Stichwortsuche bleibt übrig — die Tiefenanalyse meldet dann oft "keine relevanten Stellen".
  • Nur Gemini: OPENAI_API_KEY wäre nur ein Fallback und ist mit dem 768d-Index inkompatibel (OpenAI liefert 1536 Dimensionen). Prüfung des Live-Status: GET /debug/status → llmProviders.gemini.
Buttons:
Suchen Startet die Abfrage im gewählten Modus. performThematicSearch()
Speichern / Meine Abfragen Nur für Mitglieder: aktuelle Abfrage speichern bzw. gespeicherte Abfragen anzeigen. saveCurrentThematicSearch(), showSavedThematicSearches()

API: POST /api/thematic-hybrid-search (Parameter u.a. query, gaFilter, thematicMode) | KI: Claude / Gemini (modusabhängig, s.o.) | Embeddings: Gemini embedding-001 (768d) + Cloudflare Vectorize | Cache: thematic-search-database.json

12. Seitenumbrüche & Seitenzahlen

Übersicht

Dieses Verfahren fügt |XX| Seitenmarker in die Vorträge/Aufsätze ein. Die Marker werden aus OCR-bearbeiteten PDFs extrahiert und sowohl in die JSON-Dateien als auch in die MD-Dateien eingefügt.

PDF (Steiner_GA_pdf/)
   ↓ Seitenzahlen + Text-Fragmente extrahieren
JSON (steiner-full-lectures/)
   ↓ Text-Matching → |XX| Marker einfügen
MD (Steiner_GA/GAXXX/)
   ↓ Marker auch in MD einfügen
HTML (app.html)
   → Marker als Seitenzahlen-Badges anzeigen

PDF-Formate

Das System unterstützt drei verschiedene PDF-Formate:

Format 1: Ältere PDFs (vor ~2010)
Text des Vortrags...
Copyright Rudolf Steiner Nachlassverwaltung Seite: 42

Seitenzahl im Copyright-Footer, Muster: Copyright Rudolf Steiner...Seite: XX

Format 2: Neuere PDFs (ab ~2013, z.B. GA069b)
Text des Vortrags endet hier.
42
RUDOLF STEINER
VERLAG

Seitenzahl auf eigener Zeile, gefolgt von "RUDOLF STEINER" und "VERLAG". Header "Seite XX" am Seitenanfang wird ignoriert.

Format 3: Aktuelle PDFs
Text des Vortrags...
Seite 42

"Seite XX" am Ende der Seite (letzte 3 Zeilen)

Wichtig: PDFs müssen OCR-bearbeitet sein, damit der Text extrahiert werden kann!

Schnellstart

# Einzelne GA verarbeiten:
python tools/process_pagebreaks.py GA069b

# Bereich verarbeiten:
python tools/process_pagebreaks.py 61 67

# Trockenlauf (keine Änderungen):
python tools/process_pagebreaks.py GA069b --dry-run

Nach Abschluss: Server neu starten! (Ctrl+C, dann nb)

Das Verfahren im Detail

Schritt 1: Voraussetzungen prüfen

  • PDF vorhanden in Steiner_GA_pdf/ (OCR-bearbeitet!)
  • Vorträge exportiert in steiner-full-lectures/
  • Mapping vorhanden in lecture-page-mapping.json (optional aber empfohlen)

Schritt 2: Mapping erstellen (falls nicht vorhanden)

python tools/extract_toc.py GA069b

Extrahiert das Inhaltsverzeichnis aus dem PDF und zeigt das Mapping an. Mapping manuell in lecture-page-mapping.json eintragen!

Schritt 3: Seitenmarker einfügen

python tools/process_pagebreaks.py GA069b

Das Script macht automatisch:

  1. PDF kopieren nach Steiner_GA/GAXXX/
  2. Seitenzahlen aus PDF extrahieren (~200 Zeichen vor/nach Umbruch)
  3. Text-Matching: Position im JSON-Text finden
  4. |XX| Marker einfügen
  5. Marker auch in MD-Dateien einfügen
  6. Alte Override-Dateien deaktivieren

Schritt 4: Server neu starten

Ctrl+C
nb

Text-Matching erklärt

Das System findet die Position eines Seitenumbruchs durch Text-Matching:

  1. Aus PDF extrahieren: ~200 Zeichen am Ende der vorherigen Seite + Anfang der nächsten Seite
  2. Normalisieren: Kleinschreibung, Sonderzeichen entfernen
  3. Im JSON/MD suchen: Überlappung im Vortrag-Text finden
  4. Marker einfügen: |XX| an der gefundenen Position

Mit Mapping: Jeder Vortrag wird nur im relevanten Seitenbereich durchsucht (genauer)
Ohne Mapping: Alle Vorträge als Gesamttext verarbeitet (Fallback)
